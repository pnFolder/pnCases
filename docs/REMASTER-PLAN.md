# Remaster pnCases: план и статус

Обновлено: 2026-10-22. Выпуск называется «1.5.4 REMASTER»; версия плагина остаётся 1.5.4.

## Этап 1. Фундамент

| Задача | Статус |
|---|---|
| Разбить `CaseManager` (1260 строк) | **Готово**: фасад 417 строк + `CaseRegistry`, `CaseAdministration`, `OpeningCoordinator`, `KeyService` |
| События для других плагинов | **Готово**: `CaseOpenEvent` (отменяемое), `CaseRewardGrantEvent`, `CaseKeyGiveEvent` (`ru.privatenull.pncases.api.event`) |
| Разбить `MachineRewardScreen` (1090 строк) | **Готово**: экран 753 строки + `RewardConfigEditor` (12 тестов), `RewardSimulationScreen`, `RewardLabels`, `RewardScreenLayout` |
| Единый репозиторий данных | **Решено не делать единый кодек**: `CasesDatabase` уже общий интерфейс, а форматы SQL/Mongo/Redis различаются, смена сломала бы существующие данные. Убрано реальное дублирование (`Reward.Type.fromStored` вместо трёх копий `parseType`) |
| Миграции конфигов | **Частично**: трёхсторонняя синхронизация уже была; добавлена резервная копия конфигов и кейсов при смене версии (`ConfigBackup`, 5 тестов). Файлов с версией формата нет: формат не менялся |

## Правила работы

- Каждый шаг: сборка и все тесты (`gradlew test`), затем копирование JAR в `Servers\plugins`.
- Живую проверку на сервере выполняет владелец.
- Старые конфиги и данные хранилищ должны оставаться совместимыми.
